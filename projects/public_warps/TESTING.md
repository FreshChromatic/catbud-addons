# 貓芽公共傳點：實服測試

本地版本已可安裝測試，仍需實服紀錄驗證到達判定。這次不接入雲端。

## 50 格預覽與鏡頭測試

更新模組後，先關閉並重新啟動本地服務，讓它接收新版快照。已有 10×16×10／15×15×15／30×30×30 預覽不會憑空擴大；重新成功到達一次才擷取 50×50×50（腳下方塊各軸 -25 至 +24）。首次升級可立即上傳一次；正式預覽的替換仍先進候選，管理者核對後批准。

1. 選擇附近有動物、盔甲架或其他玩家的傳點並成功到達。檢查新版快照包含 125,000 格及實體，自己的角色沒有被記錄。共用預覽會排除所有玩家及私人文字。
2. 按 X 或輸入 `/too`，懸停傳點格子，外觀應每 8 秒旋轉一圈。
3. 單擊只選取並顯示外觀。右側按住左鍵拖曳應立即旋轉，滾輪應縮放；移出格子不應改變視角。右側預覽雙擊才平滑進入，再次雙擊返回；切換途中再次雙擊可反向中斷。拖曳後立刻點擊不應誤判為雙擊。內部亦可拖曳環視和縮放。
4. 雙擊仍執行傳送。關閉／再開啟介面，快照與個人常用次數應保留。
5. 第二個客戶端下載正式預覽後，確認方塊與實體皆可顯示。快照中的實體是靜態外觀，不會模擬移動；方塊與實體共用深度判定，部分特殊實體或材質包仍需實測。

6. 選取密集生物傳點，確認生物的尺寸、相對位置及玻璃後方遮擋正常。移開滑鼠並靜止數秒，比較卡頓情況；再測拖曳、關閉和重開。獨立測試中 173 實體場景在移開滑鼠後 2.5 秒內僅重新繪製 1 次，但完整模組組合的實際幀率仍需測試。

這次範圍改用 v4 格式，v1／v2／v3 預覽仍可使用。重啟本地服務才可接收 v4；重新到達後才擷取較大的範圍。介面不再顯示指令補全候選、已驗證回報及補全完整性提示；後台驗證仍維持。

若希望減少動畫，在服務設定 JSON 增加 `"reducedMotion":true`：停止自動旋轉，內外視角直接切換。

## 安裝與開啟紀錄

1. 從儲存庫 `out` 資料夾選擇與遊戲版本相同的 `catbud-public_warps-<版本>-1.0.3.jar`，放入該遊戲實例的 `mods`。支援 1.21.11、26.1.2、26.2、26.3，需要 Fabric Loader 與相符 Fabric API。Core 已內嵌，不需 malilib、litematica 或 SchematicPreview。
2. 先啟動一次遊戲，關閉後編輯**該遊戲實例**的 `config/catbud/public-warps-service.json`。保留服務位址，新增或修改 `traceTeleport`：

   ```json
   {"serviceUrl":"http://127.0.0.1:8787","traceTeleport":true}
   ```

3. 使用 Node.js 24 以上，在儲存庫根目錄啟動本地服務，保持終端執行：

   ```powershell
   node services/public-warps/server.mjs
   ```

   如果目前在遊戲的設定資料夾，可直接使用專案的完整路徑，無須切換資料夾：

   ```powershell
   node "C:\Users\User\Documents\GitHub\catbud-addons\services\public-warps\server.mjs"
   ```

   看到 `Catbud public warps local service: http://127.0.0.1:8787` 即表示服務已啟動。測試期間保持這個 PowerShell 視窗開啟；結束時按 Ctrl+C 停止服務。

4. 重新啟動遊戲，登入貓芽。確認按 `X` 與輸入 `/too` 都能開啟介面。在聊天輸入文字 X 時應不會打開介面。若 X 與其他模組衝突，可在控制設定改鍵。

請選擇你已知有效的公共傳點作為測試目標；不需要為測試購買月卡，設定公共傳點的擁有者有月卡即可。

## 測試順序

先記下目前版本、目標 ID 與測試開始時間。一般測試每次等待上一個流程結束，再間隔約 40 秒；快速指令測試另行進行。

| 情境 | 操作 | 要記下的結果 |
| --- | --- | --- |
| 名單與補全 | 比較聊天 `/to by ` 的補全與介面；若聊天名單疑似不完整，再手動輸入不同名稱前綴查看 | 缺少哪些 ID、是否有截斷；不要以介面收到名單代表完整 |
| 一般成功 | 手動 `/to by <有效ID>`，保持不動至到達 | 是否有 Bossbar 與 Actionbar、是否到達、個人次數是否恰好 +1、預覽是否對應實際地點 |
| 移動取消 | 再次啟動相同傳送，倒數中移動 | 是否取消、次數應不變、不應擷取錯誤地點 |
| 明確無效 | 使用你確認不存在或未設位置的 ID | 是否顯示無月卡／未設位置訊息，不應新增正式共用資料 |
| 原地傳送 | 已到達後再次傳送到同一目標 | 是否仍完成、完成時應恰好 +1；目前判定是否漏計 |
| 短距離 | 在距離目的地數格處傳送 | 與一般成功相同，次數及快照應正確 |
| 跨維度 | 選擇你知道位於其他維度的有效公共傳點 | 維度是否改變、是否成功 +1、預覽是否取自新維度 |
| 介面點擊 | 單擊選取，再雙擊有效傳點；另測底部傳送按鈕 | 單擊不傳送，雙擊與按鈕都使用相同 ID，成功時只計一次 |
| 快速兩次指令 | 短時間輸入兩個不同目標的傳送指令 | 實際到達哪個目標、有無取消；不能把前一目標的提示或快照記給後一目標 |
| 重啟保存 | 完成數次傳送後退出並重啟 | 個人前三、成功次數與本機預覽是否保留 |

若不方便找到跨維度或其他指定情境，標示「未測」，不要用其他結果替代。遇到不正確計數或快照請記下目標、時間與實際行為。

快速切換修正版：請保持診斷開啟，重測 `maiyaWEE_77` 啟動後立即改傳 `Yurui0905`，到達後等待上傳，再開 `/too` 檢查 Yurui0905 的次數與快照。新版紀錄會包含 `boss_progress`，以及即使未通過雙重提示判定也會記下的 `position_correction`。修正前漏掉的到達次數與快照不會事後補造；需以這次新的成功到達驗證。

快速切換時，伺服器可能沿用畫面上的提示而不重送翻譯文字。新版 `command` 的 `retainedLaunch` 表示保留了前一次提示的候選證據；只有新的相符 Bossbar 更新才會產生 `retained_launch_refreshed` 並啟用它。因此不能只因第二個指令缺少兩條 `translated_message` 就判定失敗。仍需核對新的位置校正、`arrival_counted`、實際目的地及恰好一次的次數變化。`enabled` 會記錄遊戲與模組版本；相同版本號的不同測試包仍請另記下載／替換時間。

## 兩個遊戲實例共用預覽

在同一電腦上用兩個獨立遊戲實例，兩者指向同一本地服務。只需第二個實例未曾造訪該傳點，不必同時登入。

1. 第一個實例傳送成功，等待本地服務收到候選；若進入審核佇列，依服務說明批准後再退出。介面不顯示「已驗證回報」，請以服務端審核結果確認。
2. 第二個實例啟動，登入貓芽，開啟 `/too` 並重新整理。
3. 第二個實例應看到相同傳點與下載的方塊預覽，自己的成功到達次數仍為 0。
4. 記下兩者遊戲版本、ID、預覽是否一致及第二個實例是否真的未曾到訪。

每個遊戲實例都需要設定服務位址；`127.0.0.1` 只連到同一台電腦。此步尚未測試不同電腦或雲端服務。

## 提供紀錄

完成後關閉遊戲，讓紀錄寫入完畢。提供：

- 遊戲版本與上述各情境的「通過／異常／未測」，尤其實際是否到達與次數變化。
- 遊戲實例中的 `config/catbud/public-warps-teleport.jsonl`；如有 `.previous`，也保留對應檔案。
- 有錯誤預覽時提供該傳點 ID、時間與問題描述；有當機時再提供對應 crash report。

診斷紀錄只在本機保存，包含目標 ID、起點／目的地座標、維度、翻譯鍵與事件時間，不含一般聊天、登入憑證或 Catbud API 詳細玩家資料，不會上傳共用服務。單檔約 1 MiB 後輪替，保留上一份；長時間測試請及時保存。

測試結束後將 `traceTeleport` 改回 `false` 並重啟。成功到達的判定仍待本次證據確認，尚不能把測試版當作已完整驗收的成品。
