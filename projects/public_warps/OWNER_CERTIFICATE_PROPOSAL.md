# 官方憑證與挑戰簽名驗證調整

狀態：2026-10-13 使用者已批准，實作與四版建置完成。WhiteMeowGX 已在獨立本機環境以真正官方 V2 憑證及挑戰簽名完成本人資訊儲存，資料庫稽核與使用者回覆均確認成功；正式雲端仍待有月卡玩家驗收。測試環境已停止，遊戲設定與快取已恢復。這份文件取代 OWNER_EDIT_PROPOSAL.md 原有 join／hasJoined 驗證方式；編輯範圍與介面維持原方案。

## 已確認的阻礙

正式 Cloudflare Worker 向 discovery.minecraftservices.com 的服務發現端點回覆 403；改為固定 sessionserver.mojang.com 的 hasJoined 端點仍回覆 403。本機服務發現請求可取得 200。尚不能確認官方拒絕的具體政策，不能把本機成功當成正式環境成功。

Workers 不接受本次使用的 redirect:error；已改成 manual，仍拒絕重新導向。修正後才確認實際上游 403。現行正式接口拒絕儲存，不會以名稱、UUID 查詢或投稿者憑證代替所有權驗證。

## 建議替代流程

1. 沿用一次性、短效挑戰與伺服器／UUID 綁定。客戶端核對包含服務來源與雙方隨機值的挑戰雜湊。
2. 模組以目前登入會話直接向固定官方 api.minecraftservices.com/player/certificates 取得帳號公鑰憑證；登入 Token 只傳給官方。憑證與私鑰僅保留在遊戲記憶體。
3. 私鑰簽署專用挑戰內容，包含本服務來源、伺服器、UUID、challengeId 與隨機挑戰雜湊。只上傳公鑰、官方憑證簽名、到期時間及挑戰簽名，不上傳私鑰或登入 Token。
4. Worker 用固定 Minecraft 官方信任公鑰驗證 publicKeySignatureV2，核對 UUID、公鑰與到期時間；再以該帳號公鑰驗證挑戰簽名。兩者通過才簽發既有五分鐘編輯憑證。
5. 沿用欄位白名單、伺服器隔離、月卡資格刷新、版本衝突、限流及稽核，不能修改其他玩家、標籤、預覽或狀態。

本機 Minecraft 26.2 的 ProfilePublicKey.Data.signedPayload 已確認官方 V2 簽名內容包含 UUID 的 16 位元組、到期時間的 8 位元組與公鑰 DER；不是可從皮膚查詢複製的材質簽名。

## 信任來源與失敗處理

不能相信玩家提供的簽發者公鑰、認證網址或「驗證成功」欄位。官方信任公鑰只從固定官方 publickeys 端點取得，由管理部署帶入已核對的官方公鑰快照；一般玩家不能更新。官方輪替使既有公鑰不適用時拒絕儲存，由管理者更新信任資料，不降級驗證。現行部署使用 src/official-certificate-keys.json 的兩個官方簽發者公鑰；tools/refresh-official-keys.mjs 可重新取得固定官方來源的 4096 位元 RSA 公鑰，顯示雜湊供檢查，核對後再部署。短效編輯憑證不超過官方憑證到期時間。

拒絕過期憑證、修改過的到期時間、錯 UUID、非官方簽名、其他服務的簽名及重放。官方憑證或私鑰被竊仍可能被冒用，不能承諾憑證外洩後仍絕對安全。

## 範圍與必要驗收

編輯視窗、資料格式、短效權限及免費 Workers＋D1 維持原方案。只替換帳號證明與雲端驗證模組，更新四版 JAR。

補一組真實密碼學驗證，涵蓋合法簽名、假簽發者、錯 UUID、過期、挑戰修改及重放；四版建置一次，再以正版帳號在遊戲完成一次正式儲存。官方憑證端點能否在實際登入會話下使用仍需驗收，不能用模擬資料宣稱正式流程完成。
