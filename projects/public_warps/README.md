# Catbud 公共傳點

支援 1.21.11、26.1.2、26.2、26.3。安裝對應 `out/catbud-public_warps-<版本>-1.0.2.jar`、`catbud-core-<版本>-1.0.2.jar` 與 Fabric API。Core 需獨立安裝一份，所有附加模組共用；不需要 malilib、litematica 或 SchematicPreview。

`X` 或客戶端 `/too` 開啟。單擊縮圖選取、雙擊傳送，底部亦有傳送按鈕。快捷鍵可於 Minecraft 控制設定修改。服務名單與伺服器補全合併顯示；雲端協議支援貓芽（catbud.net）與貓域（catrealm.net）；其他伺服器不發送指令或投稿。

## 雲端共用服務

新安裝預設使用正式雲端，不需要啟動 Node 服務：

```json
{"serviceUrl":"https://api.cbwp.workers.dev","protocol":"cloud","traceTeleport":false}
```

已有設定不會自動覆寫；更新後可修改 `config/catbud/public-warps-service.json` 並重新啟動遊戲。沒有投稿憑證仍可下載共享名單，記錄自己的補全、次數與預覽；投稿需管理者發放個別 `contributorCredential`。管理與審核方式見 [雲端服務說明](../../services/public-warps-cloud/README.md)。

## 舊版本地共用服務

需要 Node.js 24 以上，在儲存庫根目錄執行：

```powershell
node services/public-warps/server.mjs
```

預設服務 `http://127.0.0.1:8787`，SQLite 資料庫保存在 `services/public-warps/public-warps.sqlite`。服務使用真正的 Catbud API 驗證，無法連線或沒有月卡不新增正式資料。可用 `CATBUD_WARPS_PORT` 與 `CATBUD_WARPS_DB` 環境變數設定本地埠及資料路徑。

要使用舊版本地服务，在 `config/catbud/public-warps-service.json` 設定（不加入 `protocol: cloud`）：

```json
{"serviceUrl":"http://127.0.0.1:8787"}
```

兩個本地客戶端指向同一本地服務即可共用名單與方塊預覽；各自的常用紀錄仍隔離。其他電腦應使用正式雲端位址。

上傳失敗會保留佇列並逐步延長重試間隔（1–30 分鐘）。同一預覽不重複上傳，新預覽每個傳點至少間隔 30 分鐘；首次升級新版快照可立即提交一次；此紀錄重啟後保留。切換伺服器／帳號及退出遊戲會保存個人紀錄與待上傳資料。服務預設每日最多 1,000 次上游驗證，明確無效結果快取 5 分鐘，月卡有效結果快取 15 分鐘。

雙重啟動提示觸發資格驗證；成功到達後才計數及擷取快照。新版快照為 50×50×50（125,000 格），包含範圍內的靜態實體外觀。本機可顯示其他玩家；共用內容排除所有玩家、文字、箱子內容及私有資料。共用方塊狀態、相對眼睛位置／朝向及實體外觀，採遊戲模型材質，不含箱子內容或方塊告示牌文字。流體與染色採簡化顯示；方塊與實體共用立體深度判定。舊快照保留，重新到達才擷取新版。傳送完成以啟動提示後的伺服器位置校正與載入目的地作候選證據，實服的原地、跨維度、取消及其他位置校正仍需驗證，尚不能宣稱完全可靠。

共用來源回報不能證明方塊內容來自該傳點。既有快照的不同內容先進候選，管理者可於本地用 `node services/public-warps/admin.mjs candidates` 查詢，核對後 `approve <UUID>`；共用名稱可用 `name <UUID> <名稱>` 設定。管理介面不提供給模組使用者。

管理者另可用 `reject <UUID>` 拒絕候選、`remove <UUID>` 移除正式預覽、`rollback <UUID>` 回退上一份。每個傳點只保留一份前版，候選保留 7 天。這些操作均在本地資料庫執行，模組沒有管理接口。

實服測試的安裝、診斷紀錄開關與回報步驟見 [TESTING.md](TESTING.md)。診斷預設關閉，不會上傳共用服務。

## 驗證

```powershell
npm --prefix services/public-warps test
.\gradlew.bat :projects:public_warps:26.2:test
.\gradlew.bat :projects:public_warps:26.2:runClient -PverifyWarps
```

最後一項啟動獨立遊戲驗證目錄，使用合成建築快照截圖；其他支援版本亦可替換版本號執行。不連線貓芽，不代表實服傳送流程已驗證。驗證程式不包含在發布 JAR。

Workers＋D1 已部署；四個版本已完成合成快照的實際啟動、搜尋、繁體中文與視窗縮放截圖。實服成功到達、補全及兩個 Minecraft 客戶端實際捕捉與共用預覽仍需玩家驗收。

懸停格子時，縮圖每 2.5 秒交替外觀環繞與內部環視，每段旋轉 360 度；離開後退回外觀，重新懸停從外觀開始。單擊只選取、雙擊傳送。右側預覽單擊取得控制，左鍵拖曳旋轉，滾輪沿視線前後移動，可連續進出內部；外部繞目標、內部原地環視。取得控制後 WASD／Space／Shift 移動，R 或右鍵重置。按第一次 Esc、點搜尋或列表、離開預覽或視窗失焦會釋放控制；再次 Esc 關閉介面。設定 "reducedMotion":true 可停止自動旋轉與鏡頭平滑。

格子以玩家 ID 為主，自訂名稱另列第二行；右側另列自訂名稱、用途與標籤並換行顯示摘要。搜尋支援玩家 ID、自訂名稱、用途與標籤，傳送仍使用原玩家 ID，不會改用自訂名稱。

新版使用 50 格 v4 快照，相容舊預覽。開啟介面會請求伺服器補全；共用名單有 5 分鐘更新間隔，手動重新整理至少間隔 30 秒。補全出現即在本機記錄；第一次傳送失敗不列出，曾有效的傳點日後失敗仍保留並可重試。資格或可用性警告不等於禁止再次傳送。

本機資料按帳號與伺服器保存於 `config/catbud/warps/catbud/<帳號UUID>.json` 或 `catrealm/<帳號UUID>.json`。升級時會將目前貓芽連線地址對應的舊檔複製至新位置，保留原檔；不把不明舊檔匯入貓域。曾使用其他別名地址的舊檔，需確認來源後個別恢復。

共用投稿顯示實際結果：已發布、待審核、只保留本機、拒絕或過期；一般投稿不會因 HTTP 202 就標成已發布。等待審核的狀態每小時更新。重新啟動保留待上傳資料及投稿 ID；切換伺服器後，舊請求仍限制在原伺服器。管理者私人可信憑證可自動發布有效觀察與合規預覽，一般個別憑證進入網頁審核；公開 JAR 不包含任何寫入或管理憑證。

兩服新版接口已部署，Access 管理網頁已完成管理者登入與儲存驗收。管理入口為 https://control.cbwp.workers.dev ，詳細交付證據見 IMPLEMENTATION.md 的最新紀錄。

四個支援版本已加入不透明方塊的可重用頂點資料與分批上傳；縮圖與右側預覽共用同一份資料。頂點快取在幀結束按 128 MiB／64 場景回收，單一超額場景暫留，未完成上傳與遊戲共用索引不計入此預算。透明方塊及實體仍使用原本流程；首次載入、自訂模型與長時間互動效能仍待更完整驗收。

頂點每步建立最多 256 面，累積最多 2,048 面後合併上傳，減少密集場景的上傳呼叫。未完成批次的暫存記憶體會在取消時釋放，完整寫入後才公開場景。首次載入仍可能出現超過排程預算的停頓；目前測量不能保證固定幀率。

Workers／D1 的正式管理、本地模擬與驗證方式見 [雲端服務說明](../../services/public-warps-cloud/README.md)。

## 官方公共傳點名單

貓芽的傳點名單由 `https://api.catbud.net/publics` 提供，貓域使用 `https://api.catrealm.net/publics`。兩服皆不再請求 `/to by` 指令補全，也不自動逐筆提交名單發現報告。官方名單內含 UUID，因此離線玩家亦能列出；雲端服務繼續提供介紹、標籤及 3D 預覽。

名單每 5 分鐘更新一次，手動刷新間隔為 30 秒。HTTP 錯誤（包含 503）、逾時或格式錯誤會保留上次成功的名單並顯示更新失敗提示；成功回應的空陣列則代表目前沒有可用傳點。名單與更新時間會儲存在既有帳號／伺服器快取，重新連線時沿用尚未到期的快取。

從官方名單撤下的傳點保留預覽與造訪紀錄，但禁止傳送；恢復後自動啟用。玩家名稱以官方 UUID 對應的名稱為準，共享資料不會覆寫官方可用狀態。實際傳送失敗仍會即時標記不可用。

兩服的名單、更新時間和個人資料分開快取，切換伺服器時不會混用 API 回應。貓域支援以 `.` 開頭的基岩版玩家名稱；雲端服務需部署更新後的名稱驗證規則，才能接收這類玩家的預覽與回報。名單解析、撤下／恢復、改名、基岩版名稱及跨服快取測試位於 `OfficialWarpSyncTest`。
