# 玩家在遊戲內編輯自己的公共傳點

狀態：2026-10-13 已批准並實作；使用者另批准 OWNER_CERTIFICATE_PROPOSAL.md 取代下方原有 join／hasJoined 驗證。正式環境已採官方 V2 公鑰憑證與一次性挑戰簽名，四版 1.0.2 已建置，26.2 已安裝；真正正版帳號在獨立本機環境的儲存驗收已完成，正式雲端仍待有月卡玩家验收。下方會話流程保留為原方案紀錄，現行驗證以調整文件為準。

## 使用方式

選取傳點時，比對遊戲正版登入帳號 UUID 與傳點 UUID；玩家名稱只用於顯示，不能作為權限依據。傳點屬於自己、存在於目前伺服器的補全且已列入共用名單時，顯示「編輯我的傳點」。其他傳點維持查看與傳送。

表單只包含自訂名稱與用途說明，以及儲存／取消。玩家 ID 固定顯示且不可修改。標籤、可用狀態、月卡、預覽、投稿者權限及其他傳點均不在本次編輯權限內。儲存保留原標籤，成功後更新本機資訊並從雲端讀取正式結果。

## 正版與所有權驗證

不能以「名稱查得到」「UUID 是正版玩家的 UUID」「客戶端說自己是正版」驗證所有權。離線啟動器與修改過的模組可以偽造這些欄位；不能在公開 JAR 內放通用寫入密鑰。

建議使用官方 Minecraft 帳號會話的挑戰驗證：

1. Worker 建立短效、隨機、一次性的驗證挑戰，绑定要求編輯的帳號 UUID、伺服器與流程。挑戰不是永久密鑰。
2. 模組使用目前遊戲的登入會話，以官方 Authlib 的 join 協定直接向固定 Minecraft 官方 HTTPS 端點提交挑戰。為兼容各版並避免第三方認證改寫，實作直接提交 HTTP 請求。Minecraft access token 不上傳到本專案 Worker、不存入日誌或共用快取。挑戰雜湊包含本服務來源、伺服器、UUID 與雙方隨機值；客戶端先核對雜湊再提交，避免被轉用於其他伺服器登入。
3. Worker 向固定官方驗證來源核對挑戰，取得真正通過驗證的帳號 UUID，要求與挑戰 UUID 完全一致；不接受客戶端提供的驗證網址、身份結果或 UUID 替代官方回應。
4. 成功後簽發約五分鐘的專用編輯憑證，只能編輯這個 UUID 在指定伺服器的自訂名稱／用途。憑證只保存在目前遊戲記憶體，登出、切換帳號或過期後重新驗證。

已查核本機 Minecraft 使用的官方 Authlib：較舊版本使用 MinecraftSessionService，10.0.77 改為 SessionService／MinecraftServicesSessionService，兩者仍提供 joinServer 與 hasJoinedServer，但新版驗證端點採官方服務發現。實作需按版本適配，Worker 的官方端點／服務發現必須限制官方 HTTPS 來源，不能信任客戶端或第三方認證伺服器。若某版無法完成官方驗證，停止編輯，不降級為只比對名稱。

此流程驗證帳號所有權，不會自動證明玩家剛才在貓芽／貓域看到哪份補全。補全作為介面入口條件；真正的雲端授權由已驗證 UUID、指定伺服器的既有傳點及該服官方玩家接口共同決定。若遊戲伺服器 UUID 與官方正版 UUID 不一致，拒絕自助編輯，不猜測映射。

## 雲端寫入規則

專用 owner 端點在驗證後以憑證內的 UUID 定位傳點，不使用表單任意傳入的目標 UUID。再次核對目前伺服器的傳點存在、身份及月卡資格；接口故障時停止儲存，保留表單。編輯不新增傳點，不改動月卡或有效傳送證據。

只接受白名單欄位：自訂名稱最多 64 字、用途說明最多 512 字；與現有網頁資料格式相同。用途與名稱以文字顯示，不解析 HTML 或執行指令。儲存帶 expectedRevision 與 requestId，交易內檢查版本、一次性／重送及所有權；版本衝突提示重新讀取，不覆蓋其他管理者的新修改。稽核記錄實際 UUID、伺服器與變更，不記錄官方 token、短效憑證或驗證碼。

挑戰、驗證與儲存使用獨立限流、每日預算與容量上限，過期資料由既有維護流程清理，遵守免費服務及停寫限制。投稿者的私人 trusted 憑證不是帳號所有權证明，不能用它繞過 owner 驗證。正常管理網頁權限維持獨立。

## 邊界與必要驗證

非正版玩家即使改成別人的名稱或 UUID，仍不能產生該帳號的官方會話證明。另一個正版帳號也不能修改不屬於自己的 UUID。正版憑證被竊或玩家自己的電腦遭控制，仍可能被當成本人，不能承諾在這種情況下絕對安全。

只做重要驗證：一組 Worker 集成涵蓋偽身份／錯帳號／過期與重放／跨服／多餘欄位／版本衝突及合法自訂資訊更新；主要 26.2 完成一次真正正版會話驗證與儲存；其他三版建置一次。官方成功流程不能用 mock 測試代替。離線驗證失败應只禁用編輯，不影響名單下載與傳送。

本次新增需要資料表保存短效挑戰／憑證與 owner 稽核，新增雲端端點、Minecraft 帳號驗證適配及編輯表單；不要求玩家取得管理者或投稿者密鑰，也不開通付費服務。
