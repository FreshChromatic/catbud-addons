# Design System: Catbud Native Settings

## Overview

**Creative North Star: "Operate"**

The visual authority is the user's pinned EntityCulling screenshot and its native configuration provider. Catbud uses a bounded translucent dark rectangular pane, a left-aligned title, compact addon selectors, category tabs and concise settings rows. Permanent settings and floor switches share a left square pixel check/cross grammar. The user rejected the earlier full-screen layout with wide On/Off buttons.

This is a native Java Minecraft screen. Its active font, language, resource-pack item textures, sliders, edit boxes, tooltips and list interaction belong to Minecraft. `PanelButton` supplies the explicit flat frames, navigation states, footer actions and pixel checks. Density and legibility govern the system; do not add decorative branding or performance/debug counters.

**Key Characteristics:**

- A centered dark pane with clear rectangular framing.
- Title at the left; Core and installed-addon selectors at the upper right.
- Category tabs above an integrated scrolling list.
- Single-line labels, left check/cross switches and full explanatory tooltips.
- Search below the list and stable Done, Cancel, Apply and Reset actions.
- English and Traditional Chinese measured with the active game font.

## Colors

The neutral palette uses source-drawn translucent surfaces and light text. The frontmatter records explicit Java ARGB values as CSS colors; values owned by native widget resources are intentionally not sampled into tokens.

### Primary

- **Clear White** (`text-primary`): title, active labels, status values and framed action text.
- **Pixel Check Ink** (`check-ink`): enabled check and cross strokes; shape communicates the boolean value.
- **Soft Yellow Notice** (`notice`): save and error notices, backed by `notice-panel` above the pane.
- **Invalid Input Coral** (`input-invalid`): numeric and hexadecimal validation feedback.

### Neutral

- **Translucent Night Pane** (`panel`): the bounded settings surface over the game background.
- **Picker Night Pane** (`picker-panel`): the more opaque RGB/HEX dialog surface.
- **Black Frame** (`outline`), **Top Edge** (`frame-highlight`) and **Focus Edge** (`frame-focus`): hard outlines and a single inset top highlight on `PanelButton`.
- **Control Grey** (`control`, `control-hover`): resting and hovered/focused framed controls.
- **Selected / Unselected Tab** (`tab-selected`, `tab-unselected`, `tab-muted`): navigation selection without changing categories into disabled controls.
- **Unavailable Grey** (`text-unavailable`, `check-unavailable`): disabled labels and check strokes.
- **Input Grey** (`input-valid`): valid direct-entry text.

**The Source Palette Rule.** Keep custom frame colors tied to `PanelButton`; keep native slider, EditBox and textured Button rendering tied to Minecraft resources.

## Typography

All text uses Minecraft's active font at native scale. Do not prescribe a web font, fixed glyph width, synthetic weight or a custom display face. Minecraft language and resource packs determine glyph metrics, including Traditional Chinese.

The title, navigation, labels, values and footer remain compact. Ordinary rows show one concise label; explanations appear in native tooltips rather than a second permanent text line. Visible labels use the font's measured width and may clip when necessary. Hovering the label region provides separately wrapped label, explanation and live status-value lines; the wrap width is at most 250 logical units and at most screen width minus 24. Controls also retain native tooltips and narration.

**The Complete Explanation Rule.** Keep the full translated label and explanation available even when the visible row label is shortened. Do not rely on a literal newline being rendered as a tooltip line break; use measured line lists for custom row tooltips.

## Layout

Dimensions are logical Minecraft GUI units, transformed by the player's GUI scale, not physical display pixels. The centered settings pane is `min(width - 20, 680)` wide and `min(height - 24, 420)` high, with an eight-unit content inset. The title sits at pane left plus eight and top plus twelve.

Core and installed-addon selectors occupy the upper right in 20-unit-high controls, wrapping at a 22-unit pitch when needed. Category tabs follow below and wrap according to measured translated label widths. Their height is 23; a one-unit horizontal gap separates tabs. Only when usable pane width is greater than 500 do Radar, ESP, Routes, Hints and Status receive actual 16-by-16 Minecraft item-texture icons. Other categories have no substitute icon. Compact navigation is text-only.

The list begins immediately below the last category-tab row, at a 23-unit row pitch. It suppresses native list background/separator fills so the enclosing pane remains continuous. Nonboolean rows align labels left and values right. Value-control width is clamped between 130 and 200 based on half the row width. Boolean rows put an 18-by-18 check/cross at the left and the label 23 units after it. Search results retain a location button on the left and the setting control on the right.

Addon search sits below the list, 25 units above footer position, is 18 units high, and spans usable width minus ten. Core omits the search field. Footer buttons are 20 high, with width `min(96, usable / 4 - 4)` and footer top at pane bottom minus 28. Done anchors the left, Cancel and Apply follow, and Reset anchors the right. Scrolling never moves these controls.

## Elevation & Depth

Depth comes from translucent dark fill, hard black outlines and small tonal changes. `PanelButton` uses a one-unit outline plus an inset top-edge highlight; active hover or keyboard focus changes the outline to the focus color. There are no custom blur layers, floating shadows or animated lifts. Native widgets retain Minecraft's resource-defined depth and focus states.

## Shapes

Use square corners and exact rectangular silhouettes. Checks and crosses are drawn from filled pixel segments inside an 18-unit square frame. The item icons come from actual Minecraft textures. Color swatches have a black outline; they are value previews rather than decorative badges.

## Components

### Framed actions and navigation

`PanelButton` draws flat framed addon/category selectors, footer actions, RGB picker actions and check/cross controls. Nonselected navigation text is muted until hovered or focused; selected tabs use their selected fill and remain interactive. The Core selector is always present; only registered installed addons appear. Addon selection restores General and clears search. Category selection clears search.

### Boolean rows

All permanent and floor booleans use the same pixel check/cross control, never a wide textual On/Off value button. The check or cross conveys state; narration still announces translated On/Off. Disabled dependent switches preserve their values and use muted labels/strokes. Without search, the checkbox widget spans the row for a practical hit target while the visible square stays left-aligned.

### Search and scrolling rows

Search uses native `EditBox` and a translated hint. It matches setting labels, explanations and identifiers across the current addon's categories. A result's location button restores its category and scrolls to that setting. A native no-results row appears when needed. Search does not include live status/extra rows. Optional addon extra rows use the same alignment when search is empty.

### Numeric controls

Use a native slider paired with direct entry. The entry is 56 units wide; the slider uses value-control width minus 60, leaving a four-unit gap. Valid edits synchronize the draft and slider message; invalid, nonfinite or out-of-range text uses the invalid-input color and blocks Apply while present in displayed rows. Opacity is displayed and entered as a percentage while storage remains normalized. Native translated unlimited/special values stay in control messages.

### Choices and color values

Choices cycle through translated values using native `Button`. A color value uses a native Button labeled with its hexadecimal value and a framed 13-unit swatch inset into the control. It opens the RGB/HEX picker and returns only accepted changes to the parent's draft.

### RGB/HEX picker

The picker shares the dark rectangular material. Its pane width is `min(width - 32, 280)`; the frame is 184 high with twelve-unit horizontal content insets. Three native 20-unit RGB sliders appear at a 25-unit pitch with integer channel messages. The HEX input accepts exactly `#RRGGBB` in seven characters. A 14-unit-high swatch previews the current color; invalid text is coral, disables Done and shows the accepted format. Done is left and Cancel is right; acceptance returns uppercase hex. Cancel leaves the parent draft unchanged.

### Footer, notices and live rows

Done applies then closes; Apply saves and updates runtime; Cancel/Escape discards pending drafts. Category Reset changes only its draft and is unavailable for Core, Status and active search. Drafts survive addon/category changes, resize, Controls and the color picker. Notices appear just above the pane in a small dark strip, not in the scrolling rows.

Core General shows its current settings key, the native Controls entry and Minecraft-following language; About shows core and addon versions. Live status values and immediate operations share the normal row alignment. Floor switches use checks/crosses. Immediate session/floor actions are not undone by Cancel. Magic Tower's target-route key is a live General row above Controls and follows rebinding. No performance tuning or internal debug counters belong on this surface.

## Do's and Don'ts

### Do:

- **Do** preserve the bounded pane, compact top navigation, left check/cross rows, bottom search and stable footer.
- **Do** reuse Minecraft font, language, item textures and native control behavior.
- **Do** retain complete measured tooltip lines and disabled values.
- **Do** verify wide and compact native captures, English and Traditional Chinese, scrolling, dependencies, search and picker validation.

### Don't:

- **Don't** restore the rejected full-screen On/Off-button layout or permanent multiline explanations.
- **Don't** replace actual item textures with invented icons or add icons in compact navigation.
- **Don't** add rounded pills, decorative cards, custom display fonts, blur or lift animations.
- **Don't** expose internal performance/debug counters or treat an obsolete review as current visual acceptance.
